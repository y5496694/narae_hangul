# 📖 나래팩 (NaraePack) 완벽 활용 가이드

나래팩은 한컴오피스와의 완벽한 양방향 호환성을 보장하는 **HWP/HWPX 조판 엔진, AI 에이전트 스킬, 형식/문구 템플릿 및 조판 유틸리티**를 총망라한 통합 패키지입니다.

---

## 🚨 [CRITICAL RULES] 파일 편집 및 클린 작업 원칙 (반드시 준수)

1. **오직 대상 한글 파일만 남길 것 (불필요한 PDF/이미지 생성 금지)**
   * 문서 편집 요구 시, 최종 결과물은 **오직 원본 경로의 한글 파일(HWP/HWPX) 단 하나**여야 합니다.
   * 사용자가 명시적으로 요구하지 않은 PDF, 미리보기 이미지(PNG)를 영구 파일로 남겨서 폴더를 어지럽히거나 용량을 키우지 마십시오.
2. **백업 파일 생성 금지 (백업은 이용자에게 일임)**
   * `.bak`, `.backup-xxxx` 등의 백업 파일을 임의로 생성하여 폴더를 지저분하게 만들지 마십시오.
   * 백업 관리는 사용자에게 맡기며, 원본 경로의 한글 파일을 직접 깔끔하게 편집합니다.
3. **검증용 임시 파일 자율 정리 의무 (Self-Cleaning)**
   * 쪽수나 조판 확인을 위해 부득이하게 생성한 임시 PDF나 스크린샷 이미지는 **검증 완료 즉시 에이전트가 스스로 삭제**하여 어떤 흔적(찌꺼기)도 남기지 마십시오.
4. **줄 넘김 방지 자간 조판 원칙 (-10% 규칙)**
   * 줄 넘김이 살짝 발생하여 보기 깔끔하지 않을 경우 **글자 크기를 줄이지 말고 자간을 축소(-5% ~ 최대 -10%)**하여 한 줄에 맞춥니다.
   * 자간을 -10%까지 줄여도 여전히 2줄이 되면 **자간 0%로 원래 2줄 유지**합니다.
   * 표 셀 내 공백이 과도하여 줄바꿈(2줄)이 일어나는 경우(예: 답안 밑줄 란), 공백을 정밀 조절하여 불필요한 행 높이 증가를 원천 방지합니다.

## 🚀 빠른 시작 (CLI & Python)

### 1. 나래 엔진 실행
```bash
python scripts/narae.py run job.json --python python.exe
```

### 2. 기본 작업 명세서 (`job.json`) 구조
```json
{
  "schema": 1,

  "output": "output.hwpx",

    "margins_mm": [20, 20, 15, 15]

  "blocks": [ ... ]
}
```

## ⚠️ 한컴오피스 조판 엔진 vs 나래 간이 뷰어 호환성 주의사항 (필독!)

### 1. 나래 간이 뷰어(`SourceLayout`)의 한계
* 나래의 자체 `action: render`는 PySide6(Qt) 기반의 간이 추정 레이아웃을 사용합니다.
* Qt 렌더러는 한국어 전용 글꼴 행간(기본 160%), 글꼴 고유 Ascent/Descent, 표 여백을 실제보다 타이트하게 계산하므로 **화면상으로는 1쪽 안에 들어온 것처럼 보여도 실제 한컴오피스에서는 다음 페이지로 밀려날 수 있습니다.**

### 2. A4 용지 본문 가용 높이 (262mm 안전 규칙)
* **A4 세로 크기**: 210mm × 297mm
* **상·하 기본 여백**: 상단 20mm + 하단 15mm = 35mm
* **본문 순수 가용 높이**: **262mm** (머리말/꼬리말이 있을 경우 약 250mm 권장)

### 3. 표지 1쪽 밀림 방지 조판 공식
1쪽 표지 제작 시 다음 요소들의 높이와 간격 총합이 **160~180mm를 넘지 않도록** 설계해야 마지막 발행처(예: 학교명/기관명)가 2쪽으로 밀려나는 대형 참사를 방지할 수 있습니다.
* **상단 머리글/포인트 바**: 15mm 이하
* **빈 문단 간격(before 여백)**: 문단당 15~18mm 이하 권장 (30mm 이상 지양)
* **메인 제목 카드 표**: 높이 38~40mm 이하 (폰트 20~24pt)
* **하단 요약 정보 표**: 행당 높이 8~8.5mm (4행 기준 총 32~34mm)
* **발행 연월 및 기관명**: 폰트 12~16pt, after 4~5mm

## 🔄 컨셉·스타일 유지 편집 및 템플릿 저장 프로토콜 (User Interaction Rule)

### 1. 원본 문서 스타일 유지 편집 원칙
* 사용자가 기존 문서를 주며 "컨셉, 템플릿, 스타일을 유지해서 편집해줘"라고 요청할 경우:
  1. 원본 문서의 `section0.xml`, `header.xml` 내 정의된 기존 글자 모양(`charPrIDRef`), 문단 모양(`paraPrIDRef`), 테두리/배경 채우기(`borderFillIDRef`)를 그대로 계승합니다.
  2. 폰트 서체, 자간, 장평, 셀 여백, 배경색을 임의로 변경하지 않고 내용 텍스트만 자연스럽게 치환·삽입합니다.
  3. 셀 병합이나 표 확장이 필요한 경우 기존 셀의 XML 속성을 온전히 상속받도록 처리합니다.

### 2. 템플릿 추출 및 나래팩 등록 워크플로우
* 사용자가 "이 문서의 템플릿/스타일을 저장해줘"라고 요청할 경우:
  1. **사용자 확인**: 템플릿의 명칭과 용도를 어떻게 저장할지 사용자에게 먼저 질문하여 확인합니다.
  2. **템플릿 추출**: `5_유틸리티/extract_template.py`를 실행하여 해당 문서의 블록 구조, 표 규격, 여백, 스타일 정보를 추출합니다.
  3. **나래팩 영구 저장**: `3_형식템플릿/` 디렉토리 아래에 사용자가 지정한 이름으로 JSON 템플릿을 등록합니다.
  4. **재사용**: 차후 사용자가 해당 템플릿 명칭을 언급하면 해당 JSON을 기반으로 일관된 새 문서를 즉시 제작합니다.
