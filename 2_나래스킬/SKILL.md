# 📖 나래팩 (NaraePack) 완벽 활용 가이드

나래팩은 **HWP/HWPX 조판 엔진, 한컴 실행 경로, AI 에이전트 스킬, 형식/문구 템플릿 및 조판 유틸리티**를 묶은 패키지입니다. 독립 엔진의 전체 기능 일치·쪽 나눔·픽셀 일치는 보장하지 않습니다. 설치된 한컴의 기능은 [전체 COM 인터페이스](../1_나래엔진/narae-hangul/references/hancom.md)로 조회·실행하고, `verify`로 의도한 결과를 확인하세요.

문서 내용 읽기·화면 보기·PDF/PNG 출력·편집 결과의 쪽별 비교에는 [나래한글 뷰어 스킬](narae-viewer/SKILL.md)을 사용합니다. 읽기 전용 작업에는 문서 편집·저장 작업을 만들지 않습니다. `narae.py read/open/export/verify` 또는 `6_나래뷰어/narae_viewer.py`를 실제 실행하고 비교 결과와 렌더링 백엔드를 확인합니다.

## 🚨 [MANDATORY] HWP/HWPX 작업은 포함된 CLI로만 실행

이용자가 **나래한글(나래팩)을 사용하여 HWP 또는 HWPX 문서를 생성·수정·편집**하라고 요청하면, **반드시 나래팩에 포함된 CLI를 실제로 구동하여 작업해야 합니다.** 나래팩의 설명·규격·템플릿을 참고만 한 뒤 AI가 자체 코드로 한글 파일을 직접 생성하거나 편집하는 것은 금지합니다. CLI를 거치지 않으면 한글 파일 생성·수정 과정에서 문서 구조나 서식 오류가 생길 수 있습니다.

- **허용되는 방식:** 작업 JSON이나 CLI 입력을 준비하고, 포함된 `narae.py` 또는 작업에 맞는 `table_ai_commander.py`를 실제 실행하여 결과 문서를 생성·저장합니다. 한컴 COM이 필요한 작업도 포함된 CLI의 한컴 실행 경로를 사용합니다.
- **금지되는 방식:** 문서·템플릿을 읽은 것만으로 나래한글을 사용했다고 간주하거나, 별도 Python 코드로 HWP 바이너리/HWPX ZIP·XML을 직접 조립·수정하거나, CLI를 우회하는 자체 COM 스크립트로 결과 파일을 만듭니다. CLI 명령이나 작업 JSON만 작성한 것도 문서 작업 완료가 아닙니다.
- **필수 검증:** 실제 CLI 실행의 종료 코드·결과 JSON·생성된 파일을 확인합니다. 작업별 저장·요청 효과 검증이 제공되면 해당 결과도 확인하고, 실패하거나 미검증인 작업을 완료했다고 보고하지 않습니다.
- **실행할 수 없는 환경:** CLI 실행 불가 사실과 필요한 실행 환경을 알리고 중단합니다. 임의의 직접 생성·편집 방식으로 대체하지 않으며, 작업 JSON이나 실행 안내만 제공했다면 문서 자체는 아직 생성·편집되지 않았음을 명시합니다.

저장소 루트에서의 실행 예시:

```bash
python "1_나래엔진/narae-hangul/scripts/narae.py" run job.json --result result.json
```

아래 템플릿·규격·원본 스타일 지침은 **CLI 입력과 작업 명세를 준비하기 위한 참고 자료**이며, 파일을 직접 조립·수정해도 된다는 의미가 아닙니다. 이후 설명보다 이 실행 원칙을 우선합니다.

## 🚨 [CRITICAL RULES] 파일 편집 및 클린 작업 원칙 (반드시 준수)

1. **오직 대상 한글 파일만 남길 것 (불필요한 PDF/이미지 생성 금지)**
   * 문서 편집 요구 시, 최종 결과물은 **오직 원본 경로의 한글 파일(HWP/HWPX) 단 하나**여야 합니다.
   * 사용자가 명시적으로 요구하지 않은 PDF, 미리보기 이미지(PNG)를 영구 파일로 남겨서 폴더를 어지럽히거나 용량을 키우지 마십시오.
2. **백업 파일 생성 금지 (백업은 이용자에게 일임)**
   * `.bak`, `.backup-xxxx` 등의 백업 파일을 임의로 생성하여 폴더를 지저분하게 만들지 마십시오.
   * 백업 관리는 사용자에게 맡기며, 원본 경로의 한글 파일을 직접 깔끔하게 편집합니다.
3. **검증용 임시 파일 자율 정리 의무 (Self-Cleaning)**
   * 쪽수나 조판 확인을 위해 부득이하게 생성한 임시 PDF나 스크린샷 이미지는 **검증 완료 즉시 에이전트가 스스로 삭제**하여 어떤 흔적(찌꺼기)도 남기지 마십시오.
4. **줄 넘김 방지 자간 조판 원칙 (-10% 규칙)**
   * 줄 넘김이 살짝 발생하여 보기 깔끔하지 않을 경우 **글자 크기를 줄이지 말고 자간을 축소(-5% ~ 최대 -10%)**하여 한 줄에 맞춥니다.
   * 자간을 -10%까지 줄여도 여전히 2줄이 되면 **자간 0%로 원래 2줄 유지**합니다.
   * 표 셀 내 공백이 과도하여 줄바꿈(2줄)이 일어나는 경우(예: 답안 밑줄 란), 공백을 정밀 조절하여 불필요한 행 높이 증가를 원천 방지합니다.

## ⚠️ 한컴오피스 조판 엔진 vs 나래 간이 뷰어 호환성 주의사항 (필독!)

### 1. 나래 간이 뷰어(`SourceLayout`)의 한계
* 나래의 자체 `action: render`는 PySide6(Qt) 기반의 간이 추정 레이아웃을 사용합니다.
* Qt 렌더러는 한국어 전용 글꼴 행간(기본 160%), 글꼴 고유 Ascent/Descent, 표 여백을 실제보다 타이트하게 계산하므로 **화면상으로는 1쪽 안에 들어온 것처럼 보여도 실제 한컴오피스에서는 다음 페이지로 밀려날 수 있습니다.**

### 2. A4 용지 본문 가용 높이 (262mm 안전 규칙)
* **A4 세로 크기**: 210mm × 297mm
* **상·하 기본 여백**: 상단 20mm + 하단 15mm = 35mm
* **본문 순수 가용 높이**: **262mm** (머리말/꼬리말이 있을 경우 약 250mm 권장)

### 3. 표지 1쪽 밀림 방지 조판 공식
1쪽 표지 제작 시 다음 요소들의 높이와 간격 총합이 **160~180mm를 넘지 않도록** 설계해야 마지막 발행처(예: 학교명/기관명)가 2쪽으로 밀려나는 대형 참사를 방지할 수 있습니다.
* **상단 머리글/포인트 바**: 15mm 이하
* **빈 문단 간격(before 여백)**: 문단당 15~18mm 이하 권장 (30mm 이상 지양)
* **메인 제목 카드 표**: 높이 38~40mm 이하 (폰트 20~24pt)
* **하단 요약 정보 표**: 행당 높이 8~8.5mm (4행 기준 총 32~34mm)
* **발행 연월 및 기관명**: 폰트 12~16pt, after 4~5mm

## 🤖 Table & Object AI Commander 활용 가이드

AI 어시스턴트는 사용자의 자연어 요청을 [table_ai_commander.py](../5_유틸리티/table_ai_commander.py)로 실행할 수 있습니다. Windows에 한컴이 설치되어 있으면 원본 재생성 대신 검사되는 한컴 저장 경로를 사용합니다.

### 사용 예시:
```bash
# 1. 셀 내용 지정 및 서식 변경
python 5_유틸리티/table_ai_commander.py --file 문서.hwpx --command "'미정' 셀 내용을 '특이사항 없음'으로 변경하고 글자 굵게 해줘"

# 2. 셀 병합 및 내용 입력
python 5_유틸리티/table_ai_commander.py --file 문서.hwpx --command "'데이터A'와 '참고사항' 셀을 병합해서 '통합 상세 내역'이라고 적어줘"

# 3. 셀 분할
python 5_유틸리티/table_ai_commander.py --file 문서.hwpx --command "'비고' 셀을 2행으로 분할해줘"

# 4. 헤더 행 전체 스타일 및 테두리 지정
python 5_유틸리티/table_ai_commander.py --file 문서.hwpx --command "헤더 행 전체 배경색 #D0E0F0로 하고 글자 굵게 가운데 정렬해줘"

# 5. 표 위치 및 정렬 수정
python 5_유틸리티/table_ai_commander.py --file 문서.hwpx --command "표를 가운데 정렬하고 글자처럼 취급해줘"

# 6. 그림 위치 및 정렬 수정
python 5_유틸리티/table_ai_commander.py --file 문서.hwpx --command "그림을 가운데 정렬하고 글자처럼 취급해줘"
```

## 🔄 컨셉·스타일 유지 편집 및 템플릿 저장 프로토콜 (User Interaction Rule)

### 1. 원본 문서 스타일 유지 편집 원칙
* 사용자가 기존 문서를 주며 "컨셉, 템플릿, 스타일을 유지해서 편집해줘"라고 요청할 경우:
  1. 원본 문서의 `section0.xml`, `header.xml` 내 정의된 기존 글자 모양(`charPrIDRef`), 문단 모양(`paraPrIDRef`), 테두리/배경 채우기(`borderFillIDRef`)를 그대로 계승합니다.
  2. 폰트 서체, 자간, 장평, 셀 여백, 배경색을 임의로 변경하지 않고 내용 텍스트만 자연스럽게 치환·삽입합니다.
  3. 셀 병합이나 표 확장이 필요한 경우 기존 셀의 XML 속성을 온전히 상속받도록 처리합니다.

### 2. 템플릿 추출 및 나래팩 등록 워크플로우
* 사용자가 "이 문서의 템플릿/스타일을 저장해줘"라고 요청할 경우:
  1. **사용자 확인**: 템플릿의 명칭과 용도를 어떻게 저장할지 사용자에게 먼저 질문하여 확인합니다.
  2. **템플릿 추출**: `5_유틸리티/extract_template.py`를 실행하여 해당 문서의 블록 구조, 표 규격, 여백, 스타일 정보를 추출합니다.
