# 나래한글 뷰어

HWP/HWPX 읽기 전용 화면·CLI입니다. PDF와 쪽별 PNG로 출력하고 나래엔진의 결과를 한컴 기준 PDF와 전체 쪽 비교할 수 있습니다.

그림의 잘라내기·뒤집기·회색조·흑백·밝기·대비와 PDF 투명도 점무늬를 표시합니다. 불투명 BMP/PNG/JPEG/GIF의 RGB·팔레트·회색조에는 Windows GDI+ x86 축소, 중간 저장과 자동 JPEG 품질, 프린터의 그림 좌표·클립을 적용합니다. JPEG는 최대 500 dpi, 나머지는 96 dpi이며 확대하지 않습니다. GIF 팔레트·회색조는 유지하고 나머지는 RGB555 색상 점무늬를 씁니다. 같은 픽셀의 첫 JPEG 품질을 재사용하고 계산한 픽셀을 PDF에 추가 손실 없이 넣습니다. 설치된 HFT의 보통 외곽선과 명조·고딕 비트맵도 읽습니다. 남은 무늬 시작 위치·프린터 좌표·미지원 효과와 글꼴 차이는 검증 JSON의 `layout.image_limitations`, `pdf_bitmaps`, `pdf_bitmap_text`, `hft_fonts`, `font_substitutions`, `glyph_substitutions`에서 확인할 수 있습니다.

자간은 각 글자와 공백의 폭에 비율로 적용합니다. 원본 제어 문자의 UTF16 위치는 유지하면서 가짜 자간 폭을 없앴습니다. 기울임 얼굴이 없는 서체에는 기준선 중심의 약 1/3 합성 기울임을 쓰고 실제 Italic 얼굴은 유지합니다. 글자별 대체와 프린터 정수 좌표·누적 폭·PDF 정밀도는 전체 화면 일치에 남은 과제입니다. 캐시 없는 문단의 줄 높이는 `fontLineHeight` 설정을 따르며 표·도형의 `none` 채우기는 투명하게 표시합니다.

명조·고딕의 보통 비트맵은 크기별 저장 글리프·OR 축소·단어 버퍼·누적 정수 프린터 좌표를 사용합니다. HWP/HWPX의 단일 글자 208쪽과 문장 124쪽은 쪽 전체 픽셀이 일치했습니다. 혼합 글꼴·미지원 문자·굵게/기울임·장평·배분 정렬 등은 `layout.pdf_bitmap_text`의 기존 경로 사유를 함께 확인합니다. 실제 7개 문서 124쪽의 전체 무차이는 아직 달성하지 못했습니다.

보통 TTF/TTC는 설치된 원본과 Qt 글꼴 표를 대조한 뒤 힌팅 명령과 원래 글리프 경계를 보존해 PDF에 넣습니다. HFT는 Type3 외곽선을 직접 넣고, 한양 신명조·중고딕에 없는 한글은 설치된 휴먼명조·고딕의 조합 외곽선을 씁니다. 문자 종류별 파일도 같은 얼굴의 글꼴 캐시를 공유합니다. 논리 줄바꿈, 문단 기준의 정수 프린터 위치, 도형 뒤에 유지되는 PDF 수치 정밀도를 반영했습니다. HWP/HWPX 각각 101쪽의 보통 글꼴 시험이 전체 일치했습니다. `layout.pdf_native_text`에 실제 사용한 글꼴 해시와 기존 경로의 사유가 나오며, 장평은 원본 글자 폭과 프린터의 정수 평균 폭을 구분해 처리합니다. 장평·자간·정렬·글꼴 공백의 두 형식 352쪽 시험이 96 dpi에서 전체 일치했습니다. `stretched_glyphs`는 처리 수이며 끝 공백이 있는 함초롬바탕 오른쪽 정렬에는 일부 폭 차이가 남습니다. 굵게·기울임·배분 정렬과 실제 문서 전체의 차이도 계속 남아 있습니다.

그림 보조 프로그램은 Windows .NET Framework 4의 x86 컴파일러가 있으면 자체 C# 소스를 사용자 로컬 캐시에 빌드합니다. 한컴은 실행하지 않습니다. 환경이 없거나 그림 경로가 지원 범위 밖이면 `layout.pdf_bitmaps`에 원본 경로 사용과 사유를 기록합니다. 원본 알파, 그림 alpha·효과·잘라내기·반전·회전과 다른 그림 형식의 출력 차이는 남아 있습니다. 합성 시험 44쪽의 전체 일치가 실제 모든 문서의 일치를 의미하지는 않습니다.

Windows에서는 `narae_viewer.pyw`를 더블클릭하면 문서 선택창이 열립니다. Python과 엔진 의존성이 필요합니다.

```powershell
python narae_viewer.py open "보고서.hwp"
python narae_viewer.py read "보고서.hwpx" --result read.json
python narae_viewer.py export "보고서.hwp" --pdf view.pdf --png-dir pages
python narae_viewer.py verify "보고서.hwpx" --hancom --result comparison.json
```

기본값은 독립 SourceLayout입니다. 한컴 자체 조판으로 확인할 때는 `--backend hancom`을 사용합니다. 독립 모드에는 표시 차이가 남으므로 **모든 문서의 쪽수·픽셀 일치가 완료된 버전은 아닙니다.**

표 PDF는 본문에 글자처럼 놓인 한 쪽짜리 비병합 격자에서 같은 SOLID/NONE 셀 테두리와 불투명 채우기를 프린터 좌표로 출력합니다. 누적 셀 원점, 공유 선, 홀수 픽셀 두께의 비대칭 연장, 셀 내용 뒤의 경계선을 반영합니다. 두 형식 88쪽 및 기존 정밀도 4쪽이 96 dpi·오차 0으로 전체 일치했습니다. `layout.pdf_table_frames`는 처리 수와 기존 경로의 사유를 제공하며 모든 문서의 일치 판정은 아닙니다. 나뉜 표·떠 있는 표·중첩 표·점선·이중선 등 다른 선 모양는 남은 범위입니다. HWPX borderFill 두께의 16개 문자열은 정확히 구분하며, 저장은 가장 가까운 표준 두께를 사용합니다.


캐시된 단일 줄 보통 TTF의 장치 폭 보정과 소수점 크기의 논리 폭 계산 순서를 추가했습니다. Windows GDI가 선택한 글꼴의 원본 head/maxp/name 표를 검증하며 한컴 런타임에 의존하지 않습니다. 단어 뒤 공백에서 끝 보정을 정리하고 글자 종류별 묶음을 구분합니다. 캐시 표 88쪽과 3개 글꼴·3개 크기·정렬·공백 표본 2쪽이 HWP/HWPX 전체 일치했습니다. 병합 표도 완전한 직사각형 격자·SOLID/NONE 테두리 범위에서 40쪽이 추가 일치했고, 두 형식 저장 시 모든 셀에 가려진 경계를 정리합니다. 여러 줄·혼합 측정값·장평·자간 등은 장치 폭 보정 범위 밖입니다. 진단은 `device_centered_lines`, `device_metric_fallbacks`, `pdf_table_frames`를 확인하며 실제 전체 문서 무차이는 아직 미달성입니다.


혼합 SOLID/NONE 셀 테두리도 처리합니다. 서로 다른 두 선을 순서대로 그리며 같은 선은 이어지는 구간만 합칩니다. 가로선 끝은 해당 셀의 세로선 두께를 반영하고 바깥 선의 반복 순서를 유지합니다. 색·두께·NONE·바깥 경계·병합·채우기 40가지의 두 형식 80쪽이 전체 일치했습니다. 점선·이중선 등 다른 선 모양은 남은 범위입니다. 한컴 기준 출력의 버전·쪽수는 인쇄 뒤에 조회하고 `hancom_metadata_after_export`를 기록합니다.


저장된 줄의 초과 폭은 공백과 글자 사이의 순서로 압축하며 끝의 정수 나머지를 다시 정렬하지 않습니다. 셀의 BREAK/SQUEEZE/KEEP 값을 HWP/HWPX 양쪽에서 보존합니다. `layout.pdf_native_text`의 `fitted_lines`, `condensed_word_gaps`, `condensed_character_gaps`를 확인합니다. 새 합성 184쪽은 전체 일치했지만 별도 확장 검사 10쪽에는 장치 폭·셀 경계 차이가 남고, 실제 원본 전체 무차이는 아직 미달성입니다. 상세 수치는 [검증 기록](validation.md)을 확인합니다.


캐시된 장평 100% 보통 TTF의 자간은 장치 폭 보정 뒤 독립 반올림하고, 저장된 폭을 정렬에서 다시 버리지 않습니다. 세 서체·크기·양/음수 자간·정렬·소수점 폭의 본문/셀·두 형식 156쪽이 추가로 전체 일치했습니다. 장평·혼합 측정·셀 경계와 한컴 자체의 인쇄 문맥 차이는 남은 범위이며 실제 전체 무차이로 해석하지 않습니다.


지원하는 본문 인라인 표의 외곽선·비트맵·기존 painter 글자와 문단 배경을 셀의 실제 경계로 자릅니다. `layout.pdf_native_text.cell_clipped_lines`, `cell_clipped_painter_lines`와 비트맵의 `layout.pdf_bitmap_text.fitted_lines` 등은 처리 수입니다. 저장된 비트맵 줄의 초과 폭도 공백/글자 간격으로 나누며 정렬의 원래 폭을 유지합니다. 새 80쪽은 전체 일치했고 별도 64쪽은 60쪽만 일치했습니다. 그림/다른 개체 클리핑과 미지원 표·장평·스타일, 실제 문서 전체 무차이는 남은 범위입니다.

## 한컴 프로세스 수명

한컴 작업이 끝나면 브리지가 만든 문서를 닫고, 직접 시작한 프로세스의 마지막 브리지가 닫힐 때 숨은 빈 프로세스도 종료한다. PID 재사용을 막는 프로세스 핸들과 실행 파일, 전체 OS 창, 남은 문서를 확인한다. 기존 한컴과 표시 중인 창·다른 문서는 보존한다. 검증은 순차 실행하며 묶음 뒤 프로세스 수와 메모리를 확인한다. 연속 세 작업의 프로세스 종료와 중첩 문서 보존을 포함한 한컴 회귀 25개가 통과했다.
