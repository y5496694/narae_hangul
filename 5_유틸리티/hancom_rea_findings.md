# 한컴 REA 분석과 검증 범위 · 2026-10-15

대상은 설치된 한컴 2024 `13, 0, 0, 711`의 HwpAutomation.dll 및 COM 런타임이다. REA 6.5.0을 실제 실행했고, Ghidra 12.1.4의 x86 PE 분석과 REA Frida 세션으로 확인했다. DLL이나 한컴 코드를 재배포하지 않는다.

## 재현 가능한 증거

- 대상 DLL SHA-256: `20b6e320542bfc517963b3351a8a5f250ecd5411b3aeb969cf083805e6daa05d`
- Ghidra 분석: 함수 5,426개, 정의된 문자열 1,263개. 이는 한컴의 기능 수나 함수 전체의 의미를 이해한 수가 아니다.
- FilePathCheckDLL 문자열 주소: `0x1009da64`, 참조: `0x10033ad9`, `0x10033ae3`.
- 등록 분기 함수: `FUN_10033a90`, 모듈 로더: `FUN_100025f0`.
- 로더에서 현재 사용자 `Software/HNC/HwpAutomation/Modules`의 값 이름으로 DLL 경로를 읽고, 선택적 `Uses` 값을 확인한 뒤 LoadLibraryW 및 IsAccessiblePath를 사용하는 흐름을 관찰했다.
- REA Frida 관찰에서 레지스트리 키 열기는 성공했지만 값 조회가 오류 2(찾을 수 없음)를 반환했다. 실행 환경에서 보이는 레지스트리 값과 한컴 프로세스의 조회 결과가 달랐다. 별도 시험 값으로 공식 모듈을 등록한 후 RegisterModule 성공과 파일 열기를 확인했다. 기존 사용자 값과 Uses 설정을 변경하지 않았다.

## 이슈 #1과 함께 고친 문제

1. IHwpObject의 메서드 목록에는 InsertText가 없다. InsertText 액션의 파라미터셋을 만들어 Execute해야 한다.
2. 표의 실제 제어 개체 앵커로 이동하고 SelectCtrlReverse/ShapeObjTableSelCell로 진입해야 한다. 문서 시작에서 셀 이동만 실행하면 표 번호를 지정할 수 없다.
3. 병합은 실제 셀 블록을 확장해야 한다. 행 삽입은 TableInsertUpperRow/TableInsertLowerRow를 사용하며, 구조가 바뀌었는지 검사해야 한다.
4. SetItem은 모르는 항목도 받아들일 수 있다. ParagraphShape의 실제 항목은 ParaShape.AlignType이며 Align은 무시되었다. 선언 및 기본값을 검사해 모르는 이름을 실행 전에 거부한다.
5. CellShape.Item("Cell")을 수정한 뒤에는 부모 셋에 다시 넣어야 변경이 반영된다. 세로 정렬·여백이 조용히 적용되지 않던 문제를 수정했다.
6. InsertText는 LF만 주면 줄바꿈을 버렸다. 작업의 LF를 CRLF로 변환한다.
7. 일반 텍스트/서식 편집과 고급 표 편집을 같은 작업에 넣으면 일반 편집이 버려지던 경로를 수정했다.
8. 자연어 HWP 편집이 원본을 축소 모델로 재생성하던 경로는 검사되는 한컴 저장 경로로 바꿨다. 표·누름틀·지원 밖의 개체가 유실될 수 있는 재생성을 원본 편집의 자동 대안으로 사용하지 않는다.
9. DispatchEx가 기존 한컴 프로세스를 재사용할 수 있어 별도 문서 탭과 안정된 문서 ID로 작업 대상을 관리한다. 종료 시 작업 문서만 닫으며 응용 프로그램 전체 Quit을 호출하지 않는다. 중첩 COM 초기화와 해제를 짝지어 다른 자동화 연결을 유지한다.
10. 한컴 2024의 재사용된 컨트롤러에서 저장 직후 Clear가 서버 예외를 내는 사례를 재현했다. 고유한 파일 사본을 열어 디스크 내용을 검증한 다음 저장 대상 파일을 다시 연다.

## 확장 인터페이스

`hancom_capabilities`는 설치된 COM 선언을 조회한다. 해당 런타임에서 선언 항목 214개와 파라미터셋 212개를 관찰했다. 한컴 공식 ActionTable_2504에서 후보 식별자를 추출하고 CreateAction으로 조사해 849개를 카탈로그에 넣었다. 카탈로그는 실행 효과 검증 목록이 아니다.

`hancom` 작업은 원시 액션, 메서드, 속성, 파라미터 배열·중첩 셋, 반환 COM 개체 참조를 지원한다. 새 기능은 설치된 런타임의 선언과 현재 문맥을 조회하고 작업에 사용할 수 있다. 의도한 효과는 verify에 명시한다.

## 검증과 한계

회귀 테스트 21개가 통과했다. 이 가운데 16개는 설치된 한컴을 실제 호출하며, 5개는 실패 판정·HWPX 혼합 편집·출력 보존·입력 검증을 검사한다. 테스트 그룹 안에는 세 표 지정과 여러 삽입 위치 등 추가 하위 사례가 있다. 별도로 CLI의 doctor --hancom에서 엔진 0.6.0과 한컴 연결을 확인했다.

실제 한컴에서 회의록 양식을 생성하고 HWP로 저장해 표 편집을 검사했다. 세 표의 정확한 지정, 빈 셀·추가·여러 줄 입력, 텍스트 유무별 병합, 사각형 병합, 행 삽입·삭제, 단일 행 및 2×2 분할, 글자·문단·셀 서식, 표 속성, 혼합 편집, 누름틀과 중첩 파라미터 작업을 검사한다. 그림의 COM 개체 참조·크기 변경·바이너리 보존과 수식 생성도 검사한다. 원본 해시 및 관련 없는 표의 내용 보존도 검사한다.

두 자동화 세션에서 같은 파일을 열고 별도 내용을 편집한 뒤, 어느 세션을 먼저 닫아도 나머지 문서의 내용과 COM 연결이 유지되는지 추가로 검사했다. 한컴의 응용 프로그램 프로세스는 작업 종료 후 남을 수 있다. 외부 프로그램이나 사용자가 동시에 캐럿을 조작하는 경우까지 원자적으로 격리된다는 뜻은 아니며, 한컴 작업은 순차 실행한다.

실패한 액션·없는 파라미터·잘못된 인덱스가 성공으로 보고되지 않는지, 기존 출력이 실패 시 유지되는지 확인한다. 저장 후 한컴 재열기의 본문 HWPML, 서식 참조 및 내장 데이터 해시를 비교한다. 계산되는 표 전체 높이와 내부 개체 ID는 비교에서 제외한다.

전체 기능을 각각 실행한 검증, 모든 문서의 보존, 독립 엔진과 한컴의 전체 조판 일치, 픽셀 일치는 완료되지 않았다. 버전·문맥·문서 보호·대화상자·외부 연동에 의존하는 액션은 해당 환경에서 추가 검사가 필요하다. REA 분석을 수행했다는 사실만으로 기존 한컴의 모든 기능을 복제했다고 주장하지 않는다.

## 뷰어 표 원점과 실제 제목 간격의 추가 관찰

실제 문서의 제목을 REA Frida로 읽기 관찰해 논리 간격이 저장된 자간으로 계산한 값과 다름을 확인했다. 글리프 윤곽·폭은 원본과 같으며 좁아지는 원인은 미확인이다. 첫 필터의 준비 신호만 있는 결과도 보존하고, 필터를 넓힌 100회 호출의 제한된 범위와 전체 2쪽 출력 재현성을 구분한다. 독립 표 격자는 별도 한컴 PDF 경로와 두께 변환으로 검증했다. 최종 88쪽·정밀도 4쪽의 표본 일치, 실제 5/124쪽 일치와 중간 실패는 [뷰어 검증 기록](../6_나래뷰어/validation.md)을 따른다. 전체 무차이는 미달성이며 원시 문서·폰트·바이너리·REA 자료를 배포하지 않는다.


## 캐시된 글자 폭 측정

REA로 HwpApp의 논리 폭 요청 → 혼합 모듈의 전달 함수 → HncBaseDraw의 측정 및 장치 중심 보정 경로를 읽기 관찰했다. Arial AFTER의 모드별 폭과 독립 GDI 폭이 연결됐고 소수점 크기의 4단위 선행 절삭도 재현했다. 단어 끝 공백에서 보정의 범위가 끝나는 것을 전체 출력 표본으로 검증했다. 한컴 런타임을 독립 엔진에 연결하지 않고 설치 글꼴의 원본 표를 대조한다. 캐시 90쪽·병합 40쪽의 전체 일치와 남은 문맥, 메모리 부족 및 중간 실패는 [검증 기록](../6_나래뷰어/validation.md)을 따른다. 실제 전체 문서 무차이는 여전히 미달성이며 원시 자료·문서·글꼴·바이너리는 배포하지 않는다.


## 혼합 표 경계와 인쇄 전 메타데이터

한컴 PDF의 실제 선 구간·두께·색 상태(RG뿐 아니라 G의 회색 재설정 포함)를 대조해 혼합 SOLID/NONE 공유 경계와 병합 구간의 순서·가로선 연장을 맞췄다. 두 형식 80쪽의 새 전체 비교와 남은 범위는 [검증 기록](../6_나래뷰어/validation.md)을 따른다. 앞선 REA의 측정 모드 차이가 기존 표의 AFTER에서도 재발해 메타데이터 순서를 8개 출력으로 비교했다. 버전·쪽수는 인쇄 뒤에 읽도록 하고 진단과 회귀 검사를 강화했다. 이를 모든 한컴 캐시 상태의 보장으로 확대하지 않는다.


## 저장된 줄의 넘침 압축

실제 보통 TTF 제목의 줄 너비·압축 전 폭·공백 폭과 공백/글자 간 조정을 REA로 대조했다. 원본 셀은 BREAK이며 SQUEEZE 때문이라는 가설은 기각했다. 최소 원래 공백의 1/5 한도, 남은 초과 폭의 글자 간 분배, 음수 정수 나눗셈과 정렬 전 반환을 독립 구현했다. 유효한 줄 캐시를 가진 본문/셀·두 형식 184쪽이 전체 일치했다. 별도 장치 폭·셀 경계 실패와 실제 124쪽의 개선/14픽셀 회귀를 [검증 기록](../6_나래뷰어/validation.md)에 함께 기록했다. 설치 바이너리·폰트·문서·원시 분석 자료는 배포하지 않는다.


## 캐시된 TTF의 자간 순서와 저장된 폭 정렬

장치 폭 보정 뒤 별도 자간 반올림과 음수 절반 처리를 독립 구현했다. 넓은 본문의 차이가 측정 모드 때문이라는 가설은 기각했고, 줄 폭을 두 번 양자화하던 정렬을 수정했다. 156쪽의 새 본문/셀·두 형식 표본과 보존한 120쪽 부분집합이 전체 일치했다. 기존 병합 표의 55픽셀 한컴 문맥 차이가 한 번 재발해 직전/현재 독립 출력 20쪽의 동일성, 실패 로그와 한컴 재검사를 함께 보존했다. 장평·셀 경계와 실제 124쪽의 결과는 [검증 기록](../6_나래뷰어/validation.md)을 따른다.


## 셀 클립·비트맵 압축과 장치 역행렬

한컴 PDF의 셀 클립 경로를 독립 좌표로 재현하고 외곽선의 기존 행렬을 유지했다. 장치 단정밀도 행렬을 기준으로 물리 경로의 역행렬을 구해 테두리 한 모서리의 1단계 RGB 차이를 제거했다. REA에서 확인한 공통 줄 압축을 비트맵 버퍼에 확장해 새 본문/셀 출력으로 검증했다. 새 합성 80쪽과 기존 비트맵 332쪽을 재검사했고 실패와 남은 범위·실제 124쪽의 결과를 [검증 기록](../6_나래뷰어/validation.md)에 보존했다.


## 장평의 GDI 선택과 이어지는 줄

새 REA 관찰 61개 메시지에서 Arial의 선택 높이/폭 (-79,33), (-150,70)과 보통 폭 0을 확인했다. 문자 폭 44개는 설치된 원본 글꼴 표로 검증한 독립 GDI 측정과 모두 같았다. 정수 폭을 장치 측정과 캐시 키에 반영해 기존 확장 64쪽을 모두 맞췄다. 문단 끝 자간·숨은 제어 슬롯·양수 끝 자간의 줄바꿈은 한컴 PDF/배치 대조에서 추론하고 새 16쪽으로 검증했으며 내부 줄바꿈 함수를 새로 추적했다고 보고하지 않는다. 추가 24쪽과 작은 글자의 새 한컴 출력 차이는 [검증 기록](../6_나래뷰어/validation.md)에 남겼다.


## 투명 GIF 원본과 하드 마스크

REA Frida의 보정한 훅에서 23개 메시지를 잘림 없이 관찰했습니다. GdipBitmapLockBits가 원래 GIF 크기의 ARGB를 읽고 CreateBitmap/GetDIBits가 1비트 마스크와 24비트 색을 분리하는 것을 확인했습니다. PDF 대조로 첫 프레임 유지·흰 바탕·역 알파와 GIF의 무축소 경로를 검증했습니다. 초기 PNG 탐색 훅은 GetDIBits의 4번 인자를 BITMAPINFO로 잘못 읽었으므로 해당 행은 근거에서 제외했습니다. 보정한 훅은 5번 인자를 읽습니다. PNG 알파는 96dpi 축소되는 별도 경로이며 아직 GIF 구현에 포함하지 않았습니다. GIF 255/256색 경계와 같은 이미지의 배치별 품질, 작은 인라인 그림의 기준선은 통제 표본과 한컴 PDF에서 추론하고 전체 쪽으로 검증했습니다. 원시 자료·한컴 바이너리·개인 문서와 로고를 배포하지 않으며 세부 해시와 남은 실제 차이는 [검증 기록](../6_나래뷰어/validation.md)을 따릅니다.


## 비율 줄 간격과 셀 경계의 잔여 픽셀

이번 규칙은 한컴의 다시 저장한 줄 배치와 PDF를 대조해 추론했습니다. 실제 문단은 16.50pt 대신 16.52pt로 진행했고, 남은 4픽셀은 뒤따르는 셀 클립 경계에서 생겼습니다. 소수점 글자 높이의 비율 배치 42개에서 높이의 선행 4단위 절삭과 간격의 독립 부호 반올림을 확인했고 100% 미만/0%와 누적 쪽 나눔을 새 116쪽으로 검증했습니다. 고정 간격 탐색 중 HWP 값의 단위 비트와 HWPX 버전 분기 단위 오류도 발견했으며 이 비율 수정으로 해결됐다고 보고하지 않습니다. 세부 실패·해시·남은 전체 범위는 검증 기록을 따릅니다.
