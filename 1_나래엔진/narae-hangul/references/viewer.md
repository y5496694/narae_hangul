# 나래한글 뷰어 CLI

> **미완성 · 실사용 비권장 (2026-10-16 보관)**
> 한컴과 전체 화면이 같아야 한다는 목표를 달성하지 못했습니다. 사용자의 요청으로 추가 개발을 중단하고 현재 소스를 보관합니다. 일반 문서 읽기·검증의 기본 도구로 사용하지 않습니다. 상세 상태와 남은 차이는 [미완성 상태](../../../6_나래뷰어/STATUS.md)를 확인하세요.

기존 에디터의 `SourceLayout`을 편집 UI와 분리한 읽기 전용 프로그램입니다. HWP/HWPX를 열어 쪽별 내용을 읽고, 화면으로 확인하며 PDF와 PNG로 출력합니다. HWP/HWPX 저장 명령은 제공하지 않습니다.

저장소 루트에서 실행합니다. 엔진 설치는 `python "1_나래엔진/narae-hangul/scripts/narae.py" setup`을 사용합니다.

```powershell
python "6_나래뷰어/narae_viewer.py" read "문서.hwp" --pages 1,3-5 --result read.json
python "6_나래뷰어/narae_viewer.py" open "문서.hwpx"
python "6_나래뷰어/narae_viewer.py" export "문서.hwp" --pdf view.pdf --png-dir pages --dpi 144
python "6_나래뷰어/narae_viewer.py" export "문서.hwpx" --backend hancom --pdf hancom.pdf
python "6_나래뷰어/narae_viewer.py" verify "문서.hwp" --hancom --result comparison.json --diff-dir differences
python "6_나래뷰어/narae_viewer.py" verify "문서.hwpx" --reference hancom.pdf --dpi 96 --result comparison.json
```

동일한 명령을 기존 `1_나래엔진/narae-hangul/scripts/narae.py` 뒤에 붙일 수도 있습니다. 뷰어 명령은 이전 편집기 실행 파일 설정과 관계없이 포함된 소스의 읽기 전용 모듈을 사용합니다. `read --help`처럼 명령별 도움말을 볼 수 있습니다.

## 읽기 엔진

| 값 | 동작 | 검증에서의 의미 |
| --- | --- | --- |
| `independent` (기본) | 문서 안의 배치·글꼴·개체를 SourceLayout으로 직접 그림 | 한컴 없이 사용 가능. 저장된 배치와 구현 범위에 따라 한컴과 차이가 남음 |
| `hancom` | 로컬 한컴으로 개인 사본을 PDF 출력 | 한컴 조판을 사용한 기준 보기. 독립 렌더링의 일치를 뜻하지 않음 |
| PDF 입력 | PDF 그대로 표시·읽기·PNG 출력 | 주어진 PDF에 한정 |

한컴 경로는 Windows, pywin32, 설치된 한컴과 등록된 FilePathCheckDLL이 필요합니다. 기존 한컴 문서를 닫지 않고 작업이 소유한 문서 탭만 사용합니다. 문서 읽기·PDF 출력은 별도 임시 사본에서 실행하며 원본 해시를 다시 검사합니다. COM 작업 제한 시간은 `--timeout`으로 지정합니다(기본 120초). 숨은 파일 접근 확인창이 생길 환경은 오류로 반환합니다.

기준 출력은 저장된 인쇄 범위·모아 찍기·홀짝 인쇄를 이어받지 않고, 전체 논리 페이지를 1쪽씩 출력하도록 `PrintToPDFEx`를 명시합니다. 출력 PDF 쪽수와 한컴 `PageCount`도 대조합니다. 같은 Windows 세션의 나래 한컴 작업은 공유 활성 문서 충돌을 줄이기 위해 직렬 실행합니다(잠금 대기 최대 60초).

쪽수는 인쇄가 끝난 뒤 조회합니다. 미리 `PageCount`를 읽은 시험에서는 일부 TTF 간격이 1프린터 픽셀 달라졌습니다. 출력 후 최종 쪽수를 확인하고 `hancom_pagination: "print-before-count"`를 남깁니다. 관찰하지 않은 인쇄 전 쪽수는 `null`입니다. 인쇄 전에 이미 조판한 한컴 화면·PDF와의 차이까지 없어진 것은 아니므로 기준 출력 방법도 함께 기록합니다.

## 출력과 비교

- `read`: 쪽수, 선택한 쪽의 텍스트·용지 크기, SHA256, 백엔드와 한계가 담긴 JSON. 보이지 않는 Unicode 텍스트층도 읽습니다. 읽기 제한된 배포용 문서의 텍스트를 우회 추출하지 않습니다.
- `open`: 확대·쪽 이동·찾기·현재 쪽 내용·PDF/PNG 저장이 있는 읽기 전용 창. 내용 편집이나 HWP/HWPX 저장 기능은 없습니다.
- `export`: PDF 전체 문서와 `page-0001.png` 형식의 PNG. `--pages`는 PNG 범위만 선택합니다. 화면과 PNG는 같은 PDF를 사용합니다. PNG는 투명 배경을 흰 종이에 합성합니다.
- `verify`: 모든 쪽을 같은 DPI에서 비교합니다. 쪽수, 물리적 용지 크기, RGB 픽셀을 검사하며 크기 조절·좌표 정렬·허용 오차를 적용하지 않습니다. 결과의 `comparison.match`가 일치 판정입니다. 페이지가 없는 경우도 차이로 기록합니다. `--diff-dir`은 차이가 있는 같은 크기의 쪽에 대해 픽셀 차이 이미지를 저장합니다.

`verify --reference 원본.hwp`는 기본적으로 두 파일의 독립 출력끼리 비교합니다. 한컴 기준 비교는 `--hancom`, 한컴에서 만든 기준 PDF, 또는 `--reference-backend hancom`을 명시합니다. `--backend hancom --hancom`의 일치는 한컴 출력 재현성이며 독립 엔진의 완성을 증명하지 않습니다. 픽셀 차이에는 글꼴·배치뿐 아니라 PDF 이미지 압축·리샘플링·래스터라이저 차이도 포함됩니다.

종료 코드: `0` 성공/전체 일치, `1` 실행 오류, `2` 검사 완료 후 차이 발견. `success:true`는 검사가 수행되었다는 뜻이며 표시 일치와 별개입니다. 결과 JSON은 `--result`로 저장할 수 있습니다. 기존 출력 교체에는 `--overwrite`가 필요하고 입력·기준 파일·결과 JSON의 경로 충돌을 거부합니다.

## 호환성 범위

밝기·대비·그림 투명도와 회색조·흑백 조합은 REA 분석과 한컴 PNG 색상 표본으로 확인했습니다. PDF는 불투명 원본에 300 dpi의 8×8 흰 점무늬를 합성합니다. alpha 0~3은 불투명, 252~255는 생략하며 중간 단계의 무늬는 출력 순서에 따라 이동합니다. 한컴 프로세스의 앞선 출력이 시작 위치에 영향을 주므로 독립 PDF는 재현 가능한 0부터 시작하고 `alpha:native-process-brush-phase`를 남깁니다. `alpha:printer-coordinate-rounding`과 원본 알파·회전 진단도 확인합니다. `verify`는 이 차이를 보정하지 않고 그대로 검사합니다.

불투명 BMP/PNG/JPEG/GIF의 RGB·팔레트·회색조 PDF 경로는 Windows GDI+ x86을 씁니다. JPEG는 최대 500 dpi, 나머지는 96 dpi이며 확대하지 않습니다. 축소 후 JPEG는 GDI+ 기본 JPEG로 중간 저장하고 GIF는 크기를 줄일 때 GDI+ 팔레트로 저장합니다. 원래 크기의 GIF 팔레트와 8비트 회색조는 유지합니다. RGB555의 4×4 색상 양자화에서는 폭이 4n+1인 마지막 열을 세 번째 순위 열로 처리하며, PDF의 동일 픽셀 캐시는 처음 선택한 JPEG 품질을 유지합니다. 그림 위치·크기·클립은 600 dpi 프린터 격자와 PDF 숫자 정밀도로 변환합니다. 색상 점무늬와 투명도 8×8 점무늬는 별개입니다. 자체 C# 소스만 배포하고 한컴 DLL은 사용하지 않습니다. .NET Framework 4 x86 컴파일러가 없거나 원본 알파·그림 alpha·효과·잘라내기·반전·회전 등 지원 밖의 경로는 기존 표시와 사유를 `layout.pdf_bitmaps`에 남깁니다. `prepared`, `jpeg_quality_reused`, 합성 44쪽과 실제 사진 표본의 일치를 다른 문서의 전체 일치로 해석하지 않습니다.

설치된 한양 신명조·중고딕과 HCI Poppy·Hollyhock의 보통 외곽선을 읽습니다. 명조·고딕은 요청한 600 dpi 정수 em 이상인 가장 작은 저장 크기를 선택하고, 없으면 가장 큰 크기를 씁니다. 정수 픽셀 경계로 확대하며 축소할 때 모든 검정 픽셀을 OR 합성해 가는 획을 유지합니다. 보통 문장은 단어·문자 종류별 전체 버퍼로 그리며, 글자 폭을 4 HWPUNIT 격자로 반올림한 뒤 자간을 적용하고 다시 반올림합니다. 기본 반 em 공백은 버림하고 문단 마지막 글자에는 자간을 더하지 않습니다. 논리 위치의 누적 합을 600 dpi로 반올림해 버퍼 사이의 위상을 유지합니다. 기본 FontDB 대체 순서와 미지원 문자 진단도 유지합니다. `hft_fonts`의 `normal_bitmap_only`, `bitmap_renderer`, `font_substitutions`, `glyph_substitutions`, `font_fallback_config`를 확인하세요. 설치 글꼴·문자표·변환 캐시는 배포하지 않습니다. 단일 글자 208쪽과 자간·정렬·색상·2~100pt 문장 124쪽은 쪽 전체가 일치했습니다. `layout.pdf_bitmap_text`는 처리한 줄과 기존 경로 사용 사유를 기록합니다. 혼합 대체 글꼴·스타일·배경·배분 정렬 등 지원 밖의 줄은 기존 경로와 사유를 남깁니다. 처리 수와 이 표본의 일치를 실제 모든 문서의 일치로 확대하지 않습니다.

자간은 각 글자와 공백의 폭에 비율로 적용합니다. 원본 제어 문자의 UTF16 위치는 유지하면서 가짜 자간 폭을 없앴습니다. 기울임 얼굴이 없는 서체에는 기준선 중심의 약 1/3 합성 기울임을 쓰고 실제 Italic 얼굴은 유지합니다. 글자별 대체와 프린터 정수 좌표·누적 폭·PDF 정밀도는 전체 화면 일치에 남은 과제입니다. 캐시 없는 문단의 줄 높이는 `fontLineHeight` 설정을 따르며 표·도형의 `none` 채우기는 투명하게 표시합니다.

보통 TTF/TTC 글꼴은 Qt의 실제 글꼴 표와 설치 파일을 대조하고, 원본의 힌팅·글리프 경계·전역 힌팅 프로그램을 보존한 부분 글꼴로 PDF에 넣습니다. HFT는 원본 외곽선의 Type3 글꼴을 쓰며, 한양 신명조·중고딕에 없는 한글에는 휴먼명조·고딕의 조합 외곽선을 적용합니다. 원본 HFT 파일의 정수 기준선을 먼저 계산하고 문자 종류별 파일은 같은 얼굴의 256코드 PDF 캐시를 공유합니다. 한자 대체는 설치 FontDB의 Hanja 순서를 따릅니다. 캐시 없는 문단의 논리 글자 폭을 프린터 em 반올림과 구분하고, 누적 줄 위치는 문단 기준점에서 계산합니다. 도형·채운 셀이 PDF 숫자 정밀도를 바꾸면 다음 쪽에도 유지합니다.

HWP/HWPX 각각 101쪽에서 보통 TTF/TTC/HFT, 작은 글자, 색상·자간·정렬·공백 설정·혼합 글꼴·조합 한글·256코드 경계를 넘는 긴 문단의 전체 픽셀이 일치했습니다. `layout.pdf_native_text`의 `processed_lines`, `legacy_lines`, `legacy_reasons`, `fonts`의 원본 해시와 `glyph_fallbacks`를 읽으세요. 보이는 글꼴의 Unicode 매핑은 비우고 기존 의미 텍스트층을 유지해 추출 텍스트를 중복하지 않습니다. 설치 파일은 읽기만 하며 배포하지 않습니다. 장평도 설치 원본의 글자 폭과 프린터의 정수 평균 폭을 사용하며 `stretched_glyphs`로 처리 수를 기록합니다. HWP/HWPX 각각 176쪽의 장평·자간·정렬·글꼴 공백 시험이 96 dpi에서 전체 일치했습니다. 끝 공백은 정렬 폭에서 제외하지만 함초롬바탕의 추가 오른쪽 정렬 2개 표본에는 작은 글자 폭 차이가 남습니다. 굵게/기울임·배분 정렬·문자 배경과 복잡한 조합 줄은 기존 표시와 사유를 남깁니다. 처리 수와 표본 일치를 모든 문서의 일치로 확대하지 않습니다.

독립 모드는 모든 HWP/HWPX의 쪽수·픽셀 일치를 보장하지 않습니다. 미지원 스타일·문자·개체, 표·도형의 배치, 일부 그림 경로와 한컴 프로세스의 초기 점무늬 상태에 차이가 남습니다. 한컴 자체로 정확히 확인할 작업은 한컴 백엔드를 사용하고, 독립 모드 개선은 기준 출력과 별도로 비교합니다. 검증 표본과 남은 차이는 `6_나래뷰어/validation.md`를 확인하세요.

표 PDF는 본문에 글자처럼 놓인 한 쪽짜리 비병합 격자에서 같은 SOLID/NONE 셀 테두리와 불투명 채우기를 프린터 좌표로 출력합니다. 누적 셀 원점, 공유 선, 홀수 픽셀 두께의 비대칭 연장, 셀 내용 뒤의 경계선을 반영합니다. 두 형식 88쪽 및 기존 정밀도 4쪽이 96 dpi·오차 0으로 전체 일치했습니다. `layout.pdf_table_frames`는 처리 수와 기존 경로의 사유를 제공하며 모든 문서의 일치 판정은 아닙니다. 나뉜 표·떠 있는 표·중첩 표·점선·이중선 등 다른 선 모양는 남은 범위입니다. HWPX borderFill 두께의 16개 문자열은 정확히 구분하며, 저장은 가장 가까운 표준 두께를 사용합니다.


캐시된 단일 줄 보통 TTF의 장치 폭 보정과 소수점 크기의 논리 폭 계산 순서를 추가했습니다. Windows GDI가 선택한 글꼴의 원본 head/maxp/name 표를 검증하며 한컴 런타임에 의존하지 않습니다. 단어 뒤 공백에서 끝 보정을 정리하고 글자 종류별 묶음을 구분합니다. 캐시 표 88쪽과 3개 글꼴·3개 크기·정렬·공백 표본 2쪽이 HWP/HWPX 전체 일치했습니다. 병합 표도 완전한 직사각형 격자·SOLID/NONE 테두리 범위에서 40쪽이 추가 일치했고, 두 형식 저장 시 모든 셀에 가려진 경계를 정리합니다. 여러 줄·혼합 측정값·장평·자간 등은 장치 폭 보정 범위 밖입니다. 진단은 `device_centered_lines`, `device_metric_fallbacks`, `pdf_table_frames`를 확인하며 실제 전체 문서 무차이는 아직 미달성입니다.


혼합 SOLID/NONE 셀 테두리도 처리합니다. 서로 다른 두 선을 순서대로 그리며 같은 선은 이어지는 구간만 합칩니다. 가로선 끝은 해당 셀의 세로선 두께를 반영하고 바깥 선의 반복 순서를 유지합니다. 색·두께·NONE·바깥 경계·병합·채우기 40가지의 두 형식 80쪽이 전체 일치했습니다. 점선·이중선 등 다른 선 모양은 남은 범위입니다. 한컴 기준 출력의 버전·쪽수는 인쇄 뒤에 조회하고 `hancom_metadata_after_export`를 기록합니다.


저장된 줄의 초과 폭은 공백과 글자 사이의 순서로 압축하며 끝의 정수 나머지를 다시 정렬하지 않습니다. 셀의 BREAK/SQUEEZE/KEEP 값을 HWP/HWPX 양쪽에서 보존합니다. `layout.pdf_native_text`의 `fitted_lines`, `condensed_word_gaps`, `condensed_character_gaps`를 확인합니다. 새 합성 184쪽은 전체 일치했지만 별도 확장 검사 10쪽에는 장치 폭·셀 경계 차이가 남고, 실제 원본 전체 무차이는 아직 미달성입니다. 상세 수치는 [검증 기록](../../../6_나래뷰어/validation.md)을 확인합니다.


캐시된 장평 100% 보통 TTF의 자간은 장치 폭 보정 뒤 독립 반올림하고, 저장된 폭을 정렬에서 다시 버리지 않습니다. 세 서체·크기·양/음수 자간·정렬·소수점 폭의 본문/셀·두 형식 156쪽이 추가로 전체 일치했습니다. 장평·혼합 측정·셀 경계와 한컴 자체의 인쇄 문맥 차이는 남은 범위이며 실제 전체 무차이로 해석하지 않습니다.


지원하는 본문 인라인 표의 외곽선·비트맵·기존 painter 글자와 문단 배경을 셀의 실제 경계로 자릅니다. `layout.pdf_native_text.cell_clipped_lines`, `cell_clipped_painter_lines`와 비트맵의 `layout.pdf_bitmap_text.fitted_lines` 등은 처리 수입니다. 저장된 비트맵 줄의 초과 폭도 공백/글자 간격으로 나누며 정렬의 원래 폭을 유지합니다. 새 80쪽은 전체 일치했고 별도 64쪽은 60쪽만 일치했습니다. 그림/다른 개체 클리핑과 미지원 표·장평·스타일, 실제 문서 전체 무차이는 남은 범위입니다.


장평의 캐시된 TTF 장치 측정은 정수 LOGFONT 폭을 사용하며 `device_centered_stretched_lines`로 처리 수를 기록한다. 이어지는 줄의 끝 자간을 정렬에서 제외한 수는 `continuation_tracking_aligned_lines`, 숨은 앞 제어 슬롯과 양수 끝 자간을 처리한 수는 `nonbreaking_control_prefixes`, `positive_tracking_wrap_lines`다. 혼합/여러 줄 장치 측정·HFT/비트맵의 추가 줄바꿈·좁은 폭 표본과 새 한컴 출력 상태 차이는 남아 있으므로 최신 `6_나래뷰어/validation.json`의 범위를 확인한다.


투명 GIF의 PDF는 원래 픽셀 크기의 첫 프레임을 흰 바탕 RGB와 역 알파 1비트 마스크로 출력합니다. 흰 바탕 적용 뒤 255색 이하는 유지하고 256색은 RGB555 변환하며, 같은 이미지도 배치 크기별 JPEG 품질을 고릅니다. 작은 인라인 그림의 기준선과 문단 원점 반올림을 반영한 두 형식 66쪽이 새로 전체 일치했습니다. PNG 원본 알파와 그림 효과·회전·잘라내기의 결합 경로는 추가 검증 범위입니다. `layout.pdf_bitmaps`의 `source_alpha_mask_bits`, `source_frame_index`, `source_alpha_omitted`, `remaining`과 최신 전체 쪽 비교를 함께 확인합니다.


비율 줄 간격은 글자 높이의 4 HWPUNIT 선행 절삭과 간격의 독립 반올림을 반영합니다. 100% 미만의 겹침과 0% 같은 쪽 배치, 실제 넘침에서의 쪽 나눔을 구분합니다. 새 소수점·겹침·누적 116쪽이 전체 일치했고 실제 2쪽 문서의 마지막 글자 경계 차이도 없어졌습니다. 고정/여백/최소 간격의 단위는 모델의 pt 값으로 정규화하며 전체 실제 파일의 최신 결과는 검증 기록을 따릅니다.


비율 외 줄 간격은 HWP의 단위 비트와 HWPX의 직접/버전 분기를 구분해 읽습니다. 글자 단위는 문서 기본 스타일(ID 0)의 크기에서 HWPUNIT 정수로 반올림하고 고정 간격의 겹침을 유지합니다. 새 파일·줄 간격 변경은 명시적인 HWPUNIT로 기록합니다. 새 형식/조건 264쪽과 버전 분기·원본 보존 수정·구형 레코드의 별도 비교를 검증했으며 상세 범위와 중간 실패는 최신 검증 기록을 따릅니다.
